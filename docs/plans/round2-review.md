# Devin Workspaces — Round 2 Review

## Validation Mode
**Verdict: CHANGES NEEDED**

1. **[mostly resolved] V1–V5, V13:** §7 and P1 now cover folders, representative session interactions, create, two-client sync, status transitions, and phase exits. Manual real-tenant evidence is appropriate; ensure R2’s sample workflows are not treated as proof of every web interaction.
2. **[major] V6 — mostly resolved, exact ACP v1 paths need to be explicit:** `sessionCapabilities.list` is nested at `result.agentCapabilities.sessionCapabilities.list`; `loadSession` is a separate top-level capability at `result.agentCapabilities.loadSession`—not `sessionCapabilities.loadSession`. The plan’s names are correct, but specify paths and assert them in fake-agent fixtures. [ACP v1 session/list](https://agentclientprotocol.com/protocol/v1/session-list); [ACP v1 session/load](https://agentclientprotocol.com/protocol/v1/session-setup).
3. **[blocker] V7/R7 — not resolved:** The plan routes GitHub links to the pane but also offers “open in system browser”; that action contradicts “never a new external browser.” `githubusercontent.com` downloads also bypass the hosted pane, and only three GitHub hosts are listed. Remove the external-browser action for GitHub and define/test the full GitHub-link domain and download policy without silently creating exceptions to R7.
4. **[blocker] V9/C5 — splitter release is still unproven:** `screen.getCursorScreenPoint()` returns cursor coordinates, not mouse-button state; Electron’s `before-input-event` covers keyboard events, not mouse-up. If release occurs over a sibling `WebContentsView`, the shell’s `pointerup` may not arrive, and moving between child views does not itself blur the top-level window. G4 must prove a release/cancel path from both hosted views; add a reliable native/OS pointer-up mechanism or constrain the drag gesture before calling this resolved. [Electron screen](https://electronjs.org/docs/latest/api/screen); [Electron `before-input-event`](https://electronjs.org/docs/latest/api/web-contents#event-before-input-event).
5. **[blocker] C3 — the auth fallback is not acceptable as written:** Google says OAuth requests in embedded webviews are blocked; stripping `Electron/x` from the UA is not a supported way to turn an embedded view into an approved browser flow. Keep the real-IdP P0 gates, but replace UA spoofing with a supported IdP method or a system-browser/native OAuth handoff that still returns to the in-app surfaces. [Google embedded-webview OAuth policy](https://developers.googleblog.com/en/upcoming-security-changes-to-googles-oauth-20-authorization-endpoint-in-embedded-webviews/).
6. **[major] C6 — N=8 is still arbitrary:** The plan adds eviction but gives no benchmark, user-visible warning, or handling for unsaved page state. Closing an inactive `webContents` to reclaim memory can discard forms and in-page state even while tab metadata remains. Benchmark representative tab counts and define a state-safe eviction/reload policy before treating R9 persistence as satisfied. [Electron `BaseWindow` lifecycle](https://electronjs.org/docs/latest/api/base-window).
7. **[partial] V8/C8, V10/C9; [resolved] V11/V12, C1/C2/C4/C7:** Back/forward/reload and PR-subpath dedupe have plausible workflow rationale, but the rebuttal does not justify the system-browser action or every remaining browser-like control (notably copy URL). The framework wording/WinUI alternative, public-API scope, one primary Local surface, and global tabs with origin context are improved. P7 is correctly framed as evaluation, but “Local excluded” cannot count as meeting R6 on a future mobile target.
8. **[verified, not a blocker] Playwright fixture host mapping:** `_electron.launch` accepts application arguments and Electron documents `--host-resolver-rules`; the fixture approach is usable if the switch is passed before the app entry point and exercised in CI. [Playwright Electron launch](https://playwright.dev/docs/api/class-electron); [Electron command-line switches](https://electronjs.org/docs/latest/api/command-line-switches).

## Challenge Mode
**Verdict: CHANGES NEEDED**

1. **[major] Browser-surface rebuttal is only partial:** Keeping back/forward/reload is defensible if P0 demonstrates they are needed for GitHub PR navigation; dedupe is a tab-model policy, not a browser engine. But copy-URL/context-menu affordances remain extra, and “open in system browser” directly conflicts with R7. Simpler compliant alternative: retain only required title/close/reorder plus proven navigation controls, keep GitHub downloads app-owned, and remove external opening for GitHub. [Electron `shell.openExternal`](https://electronjs.org/docs/latest/api/shell#shellopenexternalurl-options).
2. **[blocker] Main-process splitter polling does not solve pointer release:** Polling position at 60 Hz does not identify mouse-up, and the named Electron input event is keyboard-only. Alternative: use a tested native pointer capture/global mouse hook, or keep the drag interaction wholly in a shell-owned native hit surface with a reliable release path; fixed presets/keyboard resize are a fallback, not proof of the proposed drag.
3. **[blocker] UA-stripping SSO fallback is a policy and reliability risk:** It attempts to make an embedded webview look like Chrome without changing its embedded nature; Google explicitly blocks embedded OAuth webviews. Alternative: use an IdP-approved non-Google method or an external/system-browser authorization handoff with a supported return flow, never copied cookies. Stop the embedded-auth path if neither works. [Google OAuth policy](https://developers.googleblog.com/en/upcoming-security-changes-to-googles-oauth-20-authorization-endpoint-in-embedded-webviews/).
4. **[major] LRU eviction at eight tabs trades memory for silent state loss:** A fixed configurable threshold is not evidence that eight is safe, and restoring a URL/title does not restore a GitHub comment draft or page state. Alternative: measure memory first; if eviction is needed, only evict clean/idle views or warn before discarding state, while preserving every open tab’s identity and ordering.
5. **[major] GitHub routing/auth policy is internally ambiguous:** `githubusercontent.com` downloads are an exception to “opens in hosted Chromium,” while “other HTTP(S) → external” conflicts with the claim that GitHub SAML IdP hops stay inside a GitHub tab. Specify source-aware, allowlisted auth redirects and test actual redirect chains; route all clicked GitHub links through the in-app view, with any download handling remaining app-owned. Electron exposes redirect events separately from ordinary navigation, so include them in the routing matrix. [Electron `webContents` navigation events](https://electronjs.org/docs/latest/api/web-contents).
6. **[major] P7 must not resolve portability by dropping Local:** Calling mobile a feasibility gate avoids promising support prematurely, but “Local excluded by nature” would narrow R6 if the mobile path is later counted as a supported target. Alternative: evaluate a Local-compatible mobile path in P7 and keep the decision explicitly pending until it preserves R6; do not label a Cloud-only mobile shell as requirement-complete.

**READY is blocked** until findings 2–6 in Validation Mode have evidence-backed resolutions, and the R7 external-browser/download policy is reconciled with the non-negotiable requirement.
