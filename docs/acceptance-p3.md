## How it is built
- `npm run dist:win` → `npm run build && electron-builder --win nsis --x64 --publish never`.
- `package.json#build`: `win.target = nsis (x64)`, `win.icon = build/icon.ico`, `nsis = { oneClick: false, perMachine: false, allowToChangeInstallationDirectory: true, deleteAppDataOnUninstall: false, artifactName: DevinWorkspaces-Setup-${version}.${ext} }`.
- **Unsigned**: `win.signExecutable: false` (replaces the earlier `signAndEditExecutable: false` so that the icon + version resources *are* written by rcedit while signing is skipped; electron-builder itself recommends this form). SmartScreen will warn when a human double-clicks the installer ("Windows protected your PC → More info → Run anyway"). Silent install from a script does not prompt (verified below). Signing via Azure Trusted Signing is deferred (plan §5).
- Fuses: `build.electronFuses` + `scripts/after-pack.cjs` (belt and braces). Verified on the *installed* exe by the smoke spec with `@electron/fuses.getCurrentFuseWire`.
- Icon: `build/icon.ico` (256 PNG + 128/64/48/32/16 DIB), generated by `node scripts/make-icon.mjs` (no dependencies; `npm run icon`). Placeholder artwork.
- Auto-update: `src/main/updater.ts` (`setupUpdater()`), wired from `src/main/index.ts` after `app.whenReady()`. Only active when `app.isPackaged && !DEVIN_WORKSPACES_TEST`; `autoDownload = true`, `autoInstallOnAppQuit = true`; first check 30 s after start, then every 6 h; events logged to `events.jsonl` as `update-check` / `update-available` / `update-not-available` / `update-downloaded` / `update-error` (`updater-disabled` when skipped). No UI yet (P5 may add a toast). Feed: `build.publish = github brianwentz/Devin-console` (from `git remote -v`), baked into `resources/app-update.yml`.

## How it is tested
`npm run smoke:install` → `scripts/smoke-install.ps1` (no admin):
1. `DevinWorkspaces-Setup-0.1.0.exe /S /currentuser /D=%LOCALAPPDATA%\Programs\devin-workspaces-smoke`
2. `tests/smoke/installed.spec.ts` (`playwright.smoke.config.ts`, phase=`fresh`) against the installed `Devin Workspaces.exe`
3. Same installer re-run over the existing install (upgrade-in-place)
4. Smoke spec again (phase=`upgrade`): the profile from step 2 must still be there and be restored
5. `Uninstall Devin Workspaces.exe /S /currentuser _?=<dir>`; assert install dir and HKCU uninstall entry are gone

The spec cannot use Playwright's `_electron.launch` on the shipped exe: Playwright attaches through `--inspect=0`, which the exe ignores because the `EnableNodeCliInspectArguments` fuse is off (by design — this is itself a positive check). Instead the exe is spawned with `--remote-debugging-port=0`, driven over CDP (`chromium.connectOverCDP`) through the shell page's real contextBridge API (`window.devinworkspaces.getState/setPaneWidth/openLink`), and main-process facts (`app.isPackaged`, webContents teardown) are read from `events.jsonl`. Views are counted via CDP `Target.getTargets` (type=page). Graceful quit is `taskkill /PID` (WM_CLOSE → `shutdown()`), so settings flush like a real close.

Not part of `npm run test:e2e`. In CI (`.github/workflows/windows.yml`) the same script runs after `dist:win`; `dist/*.exe`, `latest.yml` and `docs/evidence/*smoke*` are uploaded as artifacts.

## Caveats / open items
- **True version-to-version upgrade** is simulated by re-installing the same version over itself. A real A→B upgrade (and a live `electron-updater` download/apply) is validated by the `release.yml` workflow once two tagged releases exist — add a CI step that installs the previous release's installer first, then the current one, and reuse the `upgrade` phase of the smoke spec.
- **Unsigned**: SmartScreen warning on first manual launch of the installer. Signing (Azure Trusted Signing) is a later phase; `signExecutable: false` is the single switch to remove.
- **Publish target** is `brianwentz/Devin-console` (taken from `origin`). If the release repo differs, change `build.publish` — the value is baked into every installer's `app-update.yml`.
- `release.yml` publishes a GitHub Release draft with `GITHUB_TOKEN` on `v*` tags and asserts the tag matches `package.json#version`. Publishing the draft is a manual step.
- Installer is ~117 MB because `app.asar` (24 MB) includes production `node_modules` although `out/main.cjs` is fully bundled; adding `"!node_modules/**"` to `build.files` would trim it — left for a follow-up since P4 may need unbundled deps.
- The restored tab after upgrade points at the old fixture port (fixture servers pick random ports per run), so the upgrade phase compares URL paths, not full URLs.
